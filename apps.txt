# apps.txt — what I use on a machine that does not have the old setup.
#
# Every package here is from the Arch repos. Nothing from the other repository
# appears anywhere in this file, deliberately: that repo is going away, and a
# list for rebuilding from scratch is the wrong place to record things that will
# not be installable afterwards.
#
# Where an app I used daily only existed there, it is written as a decision to
# make rather than a package to install, near the bottom. Those are the only
# real losses.
#
# To install everything here:
#   pacman -S --needed $(grep -vE '^\s*(#|$)' apps.txt | awk '{print $1}' | tr '\n' ' ')
#
# This is not what archy needs to run; install.sh covers that. This is
# what I use.

## Install by hand, not from pacman

apple_cursor          the macOS pointer, GPL-3.0. Not in any Arch repo, so
                      it is vendored in cursors/ and install.sh copies it to
                      /usr/share/icons. Nothing to install by hand.

rust toolchain        rustup installs the toolchain into ~/.rustup, which is a
                      separate download from the rustup package itself.

ytkew                  a cargo install, not a package. Lives in ~/.cargo/bin.

zen, chrome            the browsers the keybinds use, from the repository that
                      is going away. Installed by hand and kept, so SUPER+B and
                      SUPER+SHIFT+B still work. firefox and chromium are in extra
                      and are listed above as the fallbacks.

cliamp                 a cargo install from the same repository, and the target
                      of SUPER+M. Installed by hand and kept.

These four are not on a machine that is only following this file: they come from
a cargo build or a repository that goes away, and nothing in the repos
reinstalls them. Reinstalling is part of setting up a new machine, alongside the
kernel swap noted above.


## Decisions, not packages

The pointer, the fonts and the desktop are all covered above. These are the
places where something I used is not simply an Arch package any more, so each
one needs a choice rather than an install command.

browser               I have been using Zen, which only ever came from that
                      repository. firefox and chromium are the Arch
                      equivalents and are listed above; if I want something
                      closer to what I had, there is nothing in extra that is,
                      and it stays a manual download.

vscode                the same situation, and easier: extra/code is the same
                      editor, so the Arch package is the answer and nothing is
                      lost.

neovim config          my configuration is a plugin and keybind setup, not a
                      package. It moves to a standalone ~/.config/nvim on its
                      own; archy has no opinion about it and it is not listed
                      here because there is nothing to install.

macOS pointer          apple_cursor is in no Arch repo, so it is vendored
                      in cursors/ with its GPL-3.0 license and installed
                      system-wide by install.sh. No manual step.
