# Not the full package list; that is `pacman -Qqe` and it runs to 180 lines. This
# is the subset I reach for, so that rebuilding a machine means installing these
# and not reading a list of 180 packages wondering which half matter.
#
# Where a package comes from matters more than usual here. Anything marked
# [omarchy] is built and released by that project rather than by Arch, so it
# comes out of its own repository and removing that setup removes the package.
# Those are the ones to replace or drop deliberately. Everything unmarked is in
# the standard Arch repos and needs no thought.

## Replace before the old setup goes

omarchy-nvim      [omarchy] carries a whole neovim configuration with its own
                  plugins and keybinds. It is not a plain editor package. Either
                  keep it and accept the dependency, or move the config to a
                  standalone ~/.config/nvim first and install neovim from Arch.

linux-omarchy     [omarchy] the kernel. Removing the repo takes the kernel with
                  it, so install linux, linux-firmware and regenerate the
                  initramfs before that repo is dropped, or the machine comes
                  up with no kernel.

linux-omarchy-headers  [omarchy] same, for out-of-tree modules.

sddm              login screen, if I am keeping a login screen. Not required;
                  Hyprland boots straight into a session.

uwsm              the session manager that runs the current
                  hyprland.desktop entry. archy launches apps with plain
                  setsid and does not need it, but the session entry is
                  uwsm-based, so removing it changes how the session starts.


## Not packages

A few names here are not package names and pacman will not find them, so they
are listed where they actually come from instead:

opencode                the agent I launch as a TUI. Not a package; it comes
                        from the same install path as the other agent tooling
                        under ~/.local, so it is a manual install that has to be
                        redone by hand on a new machine.

rustup                  the rust toolchain manager, not a package. It installs
                        into ~/.cargo and ~/.rustup, so reinstalling rustup
                        from the Arch repo is not enough; the toolchain itself
                        is a separate download.

apple_cursor            the macOS pointer, GPL-3.0, and the AUR package of that
                        name is not in the official repos. install.sh fetches it
                        from the release tarball when it is missing, see the
                        README.

The wayland-session-bindpid@ and wayland-wm@ units are session plumbing
provided by uwsm, not separate packages.


## Running now that nothing here starts

fcitx5            input method framework, started by an omarchy unit. My
                  profile is keyboard-us with no second language configured, so
                  it is not actually providing a second IME right now — it is a
                  leftover default. Worth wiring into autostart only if I
                  actually want to type in another language; fcitx5-gtk and
                  fcitx5-qt are the GTK and Qt frontends for it.

keyd              keyboard remapping, started as a system service by its own
                  package, so it survives on its own. The remap itself lives in
                  /etc/keyd, which is not in this repo.
